## 3. Архитектура и технологический стек
- **Фреймворк**: Next.js 14 (App Router, React 18, React Server Components, TypeScript в режиме `strict: true`). Полный запрет использования типа `any`.
- **Стилизация**: Tailwind CSS с расширенной конфигурацией темы `simona.*` (`tailwind.config.js`).
- **Анимационный движок**:
  - GSAP 3 (`gsap`, `ScrollTrigger`) для сложных скролл-анимаций, Ken Burns эффекта и параллакса;
  - Lenis Smooth Scroll (`@studio-freight/lenis` / `lenis`) через компонент `SmoothScrollProvider.tsx`;
  - Framer Motion для модальных окон, выпадающих списков и мобильных дроверов.
- **Управление состоянием**:
  - React Context + Custom Hooks (`StoreContext.tsx`): Корзина, Избранное, Сравнение, автоматическая синхронизация с `localStorage`.
- **Иконографика**: Аутентичный векторный модуль [SimonaIcons.tsx](file:///c:/Users/trash/Documents/antigravity/simona-bt_NEW/components/brand/SimonaIcons.tsx).
- **База данных и ORM**: PostgreSQL / SQLite (`prisma/schema.prisma`, Prisma Client 5.22+).
- **Валидация данных**: Схемы Zod для всех форм, API routes и вебхуков.
- **Производительность**: SSR + ISR для страниц каталога и брендов, Next/Image (WebP/AVIF), PageSpeed 90+ Desktop / 80+ Mobile, TTFB < 200 мс.

## 4. MCP Figma Protocol: Design-to-Code Pipeline
При разработке, редизайне или создании новых UI-компонентов AI-агенты **обязаны использовать MCP Figma**:

### 4.1. Доступный инструментарий MCP Figma
- `check_api_key` / `set_api_key`: Проверка сессии и готовности API-ключа Figma.
- `get_file` / `get_file_nodes`: Чтение структуры файла, страниц, фреймов, параметров Auto Layout (padding, gap, alignment), геометрии и constraints.
- `get_image` / `get_image_fills`: Экспорт изображений, иконок и графики в SVG / WebP / PNG (с поддержкой 2x/3x Retina).
- `get_team_styles` / `get_file_styles` / `get_style`: Синхронизация палитр, теней и стилей типографики.
- `get_team_components` / `get_file_components` / `get_component`: Исследование мастер-компонентов и вариантов.

### 4.2. Алгоритм переноса дизайна из Figma в код:
1. **Node Inspection**: Получить JSON узла через `get_file_nodes(file_key, ids)`.
2. **Экстракция токенов**:
   - Layout & Spacing -> Tailwind классы (`gap-4`, `p-6`, `grid-cols-12`).
   - Color Fills -> `bg-simona-surface`, `border-simona-border`, `text-simona-teal`, `text-simona-wine`.
   - Typography -> `font-montserrat text-sm tracking-wide font-medium`.
   - Corner Radius -> строго `rounded-xl` для кнопок, `rounded-md` для бейджей.
3. **Экспорт иконок**: Выгрузить SVG через `get_image(format='svg')`, очистить от жестких инлайн-цветов (`fill="currentColor"`) и зарегистрировать в `SimonaIcons.tsx`.
4. **Pixel-Perfect верификация**: Проверка соответствия размеров, отступов и цветовых контрастов на всех брейкпоинтах (Mobile 390px, Tablet 768px, Desktop 1440px, Ultra-wide 1920px).

## 6. Стандарты качества кода и инженерии интерфейсов
- **Strict TypeScript**: Никаких типов `any` и нетипизированных `props`. Все формы валидируются Zod-схемами.
- **Инварианты сборки**: Перед завершением работы код обязан компилироваться без ошибок:
  - `npx tsc --noEmit` — проверка типов;
  - `npm run build` — успешная производственная сборка Next.js.
- **Запрет мертвого кода**: Неиспользуемые импорты, закомментированные куски устаревшего кода и отладочные `console.log` должны вычищаться.
- **Интерактивная верификация верстки (Visual Feedback Loop)**:
  - Любой новый блок или редизайн проверяется через headless-инструменты или Chrome DevTools в двух обязательных разрешениях: **Desktop (1440px)** и **Mobile (390px)**.
  - Соблюдается принцип Bounded Verification (один пакетный прогон скриншотов $\rightarrow$ устранение дефектов $\rightarrow$ сдача).
- **Единый контентный слой (Single Source of Content)**:
  - Любые пользовательские тексты (заголовки, слоганы, описания преимуществ, сервисные тезисы, адреса, телефоны) **запрещено жестко зашивать в JSX**.

## 7. Универсальный стандарт наименований товаров (Product Naming Standard)
- **Статус**: Непреложное сквозное правило проекта (Universal Project Invariant).
- **Сфера применения**: Действует **везде и без исключений** — во всех разделах сайта, для всех категорий (крупная встройка, соло, малая бытовая техника, сантехника, аксессуары) и для всех брендов (Midea, ASKO, Miele, Smeg, Liebherr, Körting, Omoikiri, VARD и др.).
- **Каноническая формула**:
  $$\text{[Группа товара]} + \text{[Бренд]} + \text{[Артикул / Модель]}$$
- **Обязательные требования к частям формулы**:
  1. **Группа товара**: В единственном числе с заглавной буквы, с явным уточнением типа прибора (например: «Индукционная варочная панель», «Газовая варочная панель», «Электрическая варочная панель», «Духовой шкаф», «Встраиваемая посудомоечная машина», «Встраиваемый холодильник», «Вытяжка», «Электрический чайник»).
  2. **Бренд**: Официальное написание латиницей или кириллицей (`MIDEA`, `ASKO`, `Miele`, `Körting`, `Omoikiri`, `Smeg`, `VARD`, `Liebherr`).
  3. **Артикул**: Чистый заводской модельный код прибора (например: `MIH 45107F`, `MG 3270TGB`, `MO 78100CGB`, `HI 1995 G`, `WEA 125 WCS`).
- **Категорические запреты**:
  - ❌ **Запрещен инвертированный порядок**: недопустимы заголовки вида «Артикул + Группа» (например: `MIH 45107F Варочная панель` или `KWK 0908 G Чайник эл.`);
  - ❌ **Запрещен пропуск бренда**: название обязано содержать бренд между группой и артикулом;
  - ❌ **Запрещены складские и учетные суффиксы**: недопустимо попадание в заголовок служебных меток из 1С/склада (`FIX`, `СПЕЦ/ВИТРИНА`, `СПЕЦПРЕДЛОЖЕНИЕ`, `ПРОМО`, `АГЕНТ/БЕЗ НДС`, `УЦЕНКА`).
- **Двухуровневая архитектурная защита (Data + Runtime)**:
  1. **Data Layer**: Все записи в базе данных (Prisma PostgreSQL / SQLite) и мастер-дампе `data/exported_catalog_products.json.gz` должны быть очищены и приведены к формуле.
  2. **Runtime Layer**: Все UI-компоненты отображения (`LuxuryProductCard`, `LuxuryProductListCard`, `ProductCard`, `FastSearchModal`, `ProductBuyBox`) обязаны форматировать заголовок через единый хелпер `formatProductName(product)` из `lib/catalog/productTitle.ts`.

## 8. Идентификация товаров: SKU = Код 1С (1C SKU Identity Invariant)
- **Статус**: Непреложное сквозное системное правило (Universal Project Invariant).
- **Сфера применения**: Действует **везде и на всем сайте**: в базе данных Prisma, дампе каталога `exported_catalog_products.json.gz`, интерфейсе `ProductItem.sku`, связке промо-акций `participatingSkus`, в корзине, избранном, поиске и фидах обмена.
- **Инвариант поля `sku`**:
  - Поле `sku` **всегда и без исключений** содержит **внутренний код 1С** (числовой или учетный идентификатор номенклатуры 1С, например: `'89083'`, `'90661'`, `'85875'`, `'88149'`).
  - **Категорически запрещено** записывать в поле `sku` заводские буквенные артикулы фабрики (`OKB 1680 GN MW`, `BD 6010` и т.д.).
- **Разделение ответственности: Название (`name`) vs Код (`sku`)**:
  - **Заводской артикул модели** (`OKB 1680 GN MW`, `IHE 6041 B`, `Vision 50`, `VMC 355HK`): живет **строго внутри названия товара (`name`)** как третья составляющая канонической формулы `[Группа товара] + [Бренд] + [Модель / Заводской артикул]`.
  - **Учетный код 1С** (`89083`, `90661`, `85875`): хранится в поле `sku`.
- **Отображение в интерфейсе (UI)**:
  - Элементы витрины (`LuxuryProductCard`, `ProductBuyBox`, `CartDrawer`): плашка `Код: {product.sku}` выводит именно 1С-код (`Код: 89083`), чтобы клиент мог назвать его консультанту по телефону или в салоне.
- **Связка промо-акций (`participatingSkus`)**:
  - Массив `participatingSkus` в `data/promosData.ts` оперирует исключительно 1С-кодами (`['89083', '89082', ...]`), что обеспечивает 100% совпадение с полем `product.sku` в каталоге.

## 9. Честный статус физического присутствия (Physical Status Honesty)
- **Статус**: Непреложное сквозное системное правило (Universal Project Invariant).
- **Сфера применения**: Действует везде: в каталоге, на карточках товаров, в промо-акциях, модальных окнах и детальной карточке товара.
- **Иерархия складских статусов (Single Source of Inventory Truth)**:
  1. **«На витрине» (`SHOWROOM`)**: допустим **только и исключительно** при реальном физическом присутствии образца в салоне: `stockBelinskogo15 > 0`, либо при статусах выставки `EXHIBITION_15`, `EXHIBITION_11`, `ACTIVE_KITCHEN`.
  2. **«На складе» (`LOCAL_STOCK`)**: если прибор находится на центральном складе «СИМОНА» в Нижнем Новгороде (ул. Коминтерна, 27): `stockKominterna > 0` и `stockBelinskogo15 === 0` — статус обязан быть **`LOCAL_STOCK`** («**На складе**»). Категорически запрещено маркировать его как «На витрине».
  3. **«На удаленном складе» (`REMOTE_STOCK`)**: если прибор находится на партнерских складах дистрибьюторов в РФ (`stockRemote > 0`) при нулевых локальных остатках.
  4. **«Под заказ» (`ON_ORDER`)**: при отсутствии остатков на всех складах.
- **Запрет синтетических витринных заглушек**: При генерации промо-акций и подборе участвующих приборов запрещено принудительно проставлять `SHOWROOM` или `badge: 'На витрине'` для красоты верстки. Все складские остатки (`stockBelinskogo15`, `stockKominterna`, `stockRemote`) обязаны подтягиваться из мастер-дампа номенклатуры 1С (`data/exported_catalog_products.json.gz`) или базы данных.
